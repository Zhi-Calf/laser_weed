# 标定页面中断恢复与草稿验证

日期：2026-11-04。范围：页面、Python 服务和纯页面安装；本次没有修改 C++ 算法接口或车辆控制。

## 已实现

1. 拍照进度按会话保存在浏览器中，刷新恢复采集组和位置，并重新显示已有照片。设备 API 提供已拍位置列表；浏览器没有进度记录时，寻找当前组第一个未拍位置。近、中、远轮次可手动切换，九宫格 ✓ 标识已有照片。
2. BEV 每次点选、坐标编辑、增删点均保存本地草稿。草稿绑定会话、冻结照片和服务端点位版本；恢复草稿时隐藏旧计算结果，要求重新计算和复核。未提交时离页提醒。
3. “保存点位草稿”允许空白字段并写入设备端 `bev/draft.json`，刷新或换浏览器后可继续。草稿与严格的 `points.json` 分开；草稿存在时禁止发布。计算仍检查全部坐标、重复点、范围和拟合/检查点数量，成功保存完整点位后清除设备草稿。原先已发布的版本不会因编辑草稿而切换。
4. 内参检测保存逐图诊断。页面把无法读取、分辨率不一致、角点不足翻译成操作提示，映射到原拍摄序号并提供“去重拍”。启动失败、超时、照片数量不足等尚未进入检测阶段的问题显示整体错误，不虚构问题照片。失败诊断归档，允许在原会话重试。

## 使用边界

浏览器本地草稿依赖当前设备、浏览器和页面地址；需要换电脑、清理浏览器数据前，应点击“保存点位草稿”。保存到设备的草稿可继续使用。重新拍摄地面照片会清空该照片的旧点位。

上述结果是模拟输入和软件流程验证。真实相机拍摄、RTK 同步、板端部署及装车几何精度仍需实机验证。
