# 图像时刻姿态驱动的动态 BEV

## 实现与坐标

`DynamicBevProjector` 读取相机内参和显式安装外参，根据图像对应的 roll/pitch
重算平面单应矩阵，交给原有行提取、拟合与跟踪管线。不直接修改最终横向/航向误差，
不实现 GNSS 位置滤波、传感器驱动或车辆控制。

相机坐标为 OpenCV 光学轴（右、下、前），车辆为 ROS 轴（前、左、上）。
刚体外参定义 `p_B = R_BC p_C + t_BC`，旋转必须为正交且行列式 +1 的 3×3 矩阵，
平移是相机光心在车体坐标的位置，单位 m。`origin_height_m` 是车体参考点相对地面的
垂直高度，不是镜头离地高度；`base_link` 在地面时可以为 0，但相机仍须位于地面上方。

局部地面假定水平，车体到水平参考系姿态为 `R_GB = Ry(pitch) Rx(roll)`。
重力上方向在车体中为 `n_B = R_GBᵀ [0,0,1]`，地面为
`n_Bᵀ p_B + h = 0`。由此用车体 x/y 表示地面点：

```
z_B = (-h - n_x*x_B - n_y*y_B) / n_z
pixel ~ K R_BCᵀ ([x_B,y_B,z_B]ᵀ - t_BC)
```

将上式整理为地面 x/y 到图像的 3×3 映射，求逆并接原 BEV 栅格变换。
输出仍是**车体坐标 x/y 分量**，不是把水平参考系伪称为 `base_link`，
因此沿用原 SDK 符号及直线定义。yaw 对水平面法向无影响，不用于该平面补偿。
对相机后方/光学深度小于等于 5 cm 的地面像素进行屏蔽，避免逆投影镜像。

## 配置与失效

模板在 `configs/bev.example.yaml`。动态块默认关闭；原内参、BEV 的验收标记也必须有效。
动态参数须与同一安装状态、同分辨率、同去畸变内参的实测 BEV 对应。
创建句柄时在参考姿态下，对 x=1/3/5 m、y=-0.5/0/0.5 m 共 9 个点进行米制一致性检查，
默认最大偏差 5 cm。该检查只是拒绝明显不一致的标定，不是现场精度验收。

`max_tilt_rad` 限制绝对 roll/pitch，`max_attitude_age_ms` 限制姿态与图像的采集时间差。
ROS 适配器还会检查发布者、帧名、有效状态和相对参考姿态的变化量。
启用后遇到缺姿态、过期、未来时间、NaN、超限或投影退化，必须输出无效结果，
不能使用上一帧矩阵或退回静态投影假装补偿成功。

SDK 使用新增的逐帧 C 接口，不更改已有 ABI v1 结构布局。
`PerceptionPipeline` 接收只在本次调用有效的投影器，串行 handle 的跟踪器不会被每帧重建。
本次只修正地面几何，不提供 GNSS 平移/速度驱动的目标跟踪运动预测。

## 已知限制

- 不估计地面坡度、局部起伏、车体参考点垂向升沉或相机支架弹性。
- 在斜坡上，车体相对世界的俯仰不等于相机相对当地地面的俯仰；此模型不能保证正确。
- 目前采用最近的因果姿态样本，不等待未来姿态、不插值、不外推到图像时刻；
  应按实际消息频率和运动幅度设定龄期预算，不把示例 50 ms 当成普适保证。
- 设备轴与车体轴必须已对齐，否则应先通过安装旋转变换姿态，不能只改帧名。
- 公开数据集图片不能套用这台相机的外参作为米制导航验收。
